# Session S9 decisions

S9 is a follow-up session that `docs/PLAN.md` does not list: David asked for the never-matching checks behind his SigmaHQ fixes to become part of Centinela, with the bugs that are fixed upstream and the ones that are not recorded in the repository. It adds `npm run rules:lint`. Like S8, it updates the READMEs because David asked for it; it leaves the PLAN status table to David.

## S9-01 — `npm run rules:lint`: static checks for Sigma conditions that can never match (2026-11-06, S9)

A Sigma rule can load, compile and pass SigmaHQ's own tests and still never match, because a value contradicts the shape of the field it tests: `Image: '\AgentExecutor.exe'` (Sysmon logs a full path), `CommandLine: ' -dhl'` (an exact command line has no leading space), `OriginalFileName: '\msiexec.exe'` (the field is a bare file name). The rule, or one of its filters, is dead and nothing says so. `packages/server/src/detection/lint.ts` checks every detection item for eight classes, each taken from fixes merged in SigmaHQ in October and November 2026 (SigmaHQ/sigma#6453, #6454, #6455, #6483, #6518, #6546, #6549, #6554, #6560, #6562, #6565 and #6567): `partial-path`, `folder`, `bad-start`, `separator`, `file-name`, `cmd-space`, `dword` and `unsatisfiable` (`docs/DETECTION.md#rule-lint` has the table). Values are parsed with the engine's own `parseSigmaString`, so `\\`, `\*` and `\?` are escapes exactly as in pySigma, and `unsatisfiable` compiles the other items of the same field with the engine's `compileDetectionItem` and tests each exact value on an event that holds only that field: it can only report a contradiction within one field of one selection, never across fields. Items with a modifier the engine does not support are skipped instead of failing the rule, so rules the engine cannot compile are still checked.

The bar for a check is that every finding on SigmaHQ's master branch is a condition that cannot match in the logs the rule is written for; a lint that a maintainer is asked to run cannot cry wolf. That bar set the details: path fields are only `Image`, `ParentImage`, `ImageLoaded`, `TargetFilename`, `SourceImage` and `TargetImage` (`CurrentDirectory` ends with a separator by design); a path is full when it starts with a drive, `\\`, `\Device\`, `\SystemRoot\`, `\??\`, `%` or `/`; the names Windows logs for processes without an image file (`System`, `Registry`, `MemCompression`, `vmmem` and a few more) are accepted; `startswith` and wildcard values only need a beginning that some full path can have (`C`, `\Dev`); the separator check needs `logsource.product` and stays silent without it; the registry check applies to Sysmon's `Details` only. Against history, each of the twelve pull requests was checked on the versions of its files before and after the merge (`git show <merge>^1:<file>` and `<merge>:<file>`): the lint flags 28 of the 29 files before (the 29th, in #6567, is a misspelled registry key) and nothing after, except `Image|endswith: '/xwizard.exe'` in the version of #6546 that was merged, which #6562 fixed. On SigmaHQ master `53b90df6` (2026-11-06) the lint reports 5 values in 4 active rules (an Avira filter with exact folder paths, `OriginalFileName: '\REGSVR32.EXE'`, a `/usr/share/icons/` filter in a Windows rule and `ParentImage|endswith: '\bash'` in a Linux rule) and 14 in `deprecated` and `unsupported`; each one was read by hand.

## S9-02 — Known findings live in a baseline that cannot go stale (2026-11-06, S9)

The vendored rules must not be edited (DRL 1.1, CLAUDE.md), so findings in them are recorded, not fixed. `rules/lint-baseline.json` lists them with where each stands upstream; it sits next to the rules it describes (`rules/` is outside Prettier) and is validated with zod (unknown keys refused). An entry matches every finding with the same file, check and key, not value: the Quarks rule has seven bad values under one key, and the vendored rules only change when the subset is updated, which is exactly when the baseline is reviewed. The command exits with 1 on a finding the baseline does not list, on an entry that matches nothing any more (the rule was fixed or removed) and on a file it cannot read; 2 on bad arguments. `npm test` holds the same comparison and pins the rules by upstream status. Today: 22 findings in 14 vendored rules; 13 rules are fixed after the vendored commit `05d1031f` (SigmaHQ/sigma#6546, #6549, #6565 and #6567) and the fix for `proc_creation_win_regsvr32_remote_share.yml` is proposed in SigmaHQ/sigma#6577, opened by David with the other new findings on master (the Avira filter and the Spark rule). Updating `rules/sigma` turns the fixed ones into stale entries to delete; `rules/sigma/README.md` says so.

## S9-03 — Any folder of Sigma rules, every document of a file (2026-11-06, S9)

`--rules-dir` takes Centinela's `rules/` (recognized by its `sigma/`, `centinela/` or `correlation/` folders, and listed with the rule loader so the regression samples are skipped) or any other folder, such as a SigmaHQ checkout, where every `*.yml` and `*.yaml` file below it is checked (symbolic links not followed, files above 1 MB refused, as the loader does). The baseline defaults to `<rules-dir>/lint-baseline.json` when it exists; `--baseline` and `--no-baseline` override it and cannot be combined. YAML is parsed with the loader's options (unique keys, alias limit), but a multi-document file, which the loader refuses, is checked document by document: SigmaHQ's `unsupported` folder still has old rule collections. Relative paths resolve from the folder where `npm run` started (`INIT_CWD`), like the other commands.

## S9-04 — Option names in validation errors (2026-11-06, S9)

The commands' argument parsers reported zod issues with the schema's key, so an empty `--rules-dir` printed `--rulesDir: ...`, an option that does not exist. `formatIssues` in `packages/server/src/detection/cli/args.ts` now converts the key to the option's kebab-case name, for `rules:report`, `bench` and `rules:lint`; `test/detection/cli.test.ts` covers it.
