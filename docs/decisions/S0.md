# Session S0 decisions

## S0-01 — TypeScript 6.0, not 7.0 (2026-10-26, S0)

TypeScript 7.0 (the native compiler) is the newest release, but `typescript-eslint` 8.72 supports `typescript >=4.8.4 <6.1.0`, and type-aware linting is part of the quality bar. The repository pins `typescript ~6.0.3`. Because TypeScript 6 defaults `types` to `[]`, `tsconfig.base.json` sets `"types": ["node"]` explicitly (the web app overrides it with `vite/client`). Revisit when `typescript-eslint` supports 7.x.

## S0-02 — Workspace packages export sources under a custom condition (2026-10-26, S0)

`@centinela/shared` exports `./src/*.ts` under the `@centinela/source` condition and `./dist/*.js` otherwise. Typechecking (`customConditions`), Vitest and Vite (`vitest.shared.ts`) and `tsx` (`--conditions=@centinela/source`) resolve the sources, so tests, `npm run dev` and the CLIs never need a prior build. Production builds (`tsconfig.build.json` clears `customConditions`) and the Docker images use `dist`. Consequence: `npm run build` builds `shared` first, then the other packages.

## S0-03 — ATT&CK helper: pure index plus a Node-only loader (2026-10-26, S0)

`createAttackIndex(data)` (main entry, browser-safe) validates the data with zod and maps technique ids to name, tactics and URL; `tacticsFor()` returns tactic shortnames de-duplicated in matrix order; `techniquesFromTags()` extracts `attack.tNNNN[.NNN]` tags upper-cased. Reading `data/mitre-attack/enterprise-attack.min.json` from disk lives in `@centinela/shared/node` (`loadAttackIndex`, `loadAttackIndexSync`); ESLint forbids importing it from the web package. A sub-technique missing from the data falls back to its parent's tactics and URL (keeping its own id), so a rule tagged with a newer sub-technique still gets tactics; an unknown technique yields no tactics.

## S0-04 — API contract details not fixed by ARCHITECTURE §9 (2026-10-26, S0)

Recorded in `packages/shared/src/api.ts`:

- `status` and `level` filters accept a comma-separated list or a repeated parameter (`level=high,critical`); other filters take one value. Query booleans are the strings `true`/`false` (never `z.coerce.boolean`, which turns `"false"` into `true`).
- `from`/`to` accept ISO 8601 with `Z` or an offset; `from` must not be after `to`; the server applies the 24-hour default.
- Ingest query: `host` defaults to `unknown` and allows `[A-Za-z0-9._-]` only; `tz` must be a valid IANA zone (default `UTC`).
- Triage bodies are strict objects (unknown keys rejected). Closing requires a `resolution`; any other status must not carry one. Notes are at most 4,000 characters, bulk requests at most 500 ids, JSON bodies at most 100 kB.
- `GET /api/alerts/:id` returns `rule: null` when the rule is no longer loaded (an alert outlives a deleted rule file).
- Stats overview: `byLevel`/`byStatus` contain every level/status; time series are `{ t, count }`; top lists are `{ ip|user, count }` and `{ ruleId, title, level, count }`. ATT&CK response techniques carry `rules` (enabled, supported rules) and `alerts` (in range) counts.
- Rule ids in paths are validated with `z.guid()` (any 8-4-4-4-12 hex id) because some community rule ids are not RFC 9562 UUIDs; event and alert ids use `z.uuid()`.

## S0-05 — Migrations are plain SQL files in `packages/server/migrations/` (2026-10-26, S0)

`001_initial-schema.sql` is the SQL of ARCHITECTURE §8 verbatim, loaded by node-pg-migrate's SQL loader (`-- Up Migration` / `-- Down Migration`). Plain SQL keeps the schema reviewable and identical to the contract; the folder sits outside `src/` because it is not compiled and the runtime image copies it as is. `npm run db:migrate` runs `src/db/cli/migrate.ts` (our config, redacted URL in output, exit code 1 on failure) instead of the node-pg-migrate CLI. The runner waits for the advisory lock (`advisoryLockMode: 'wait'`), so parallel test files and two containers starting together serialize instead of failing. `test/helpers/db.ts` migrates into a random `test_<hex>` schema and returns a pool whose connections set `search_path` through the startup `options`, so queries need no schema prefix.

## S0-06 — Configuration rules (2026-10-26, S0)

Empty environment values count as unset. Relative `RULES_DIR`/`CONTENT_DIR` resolve against the repository root, not the process working directory (`npm run -w` changes it). In production the server refuses the development `INGEST_TOKEN`, any token shorter than 32 characters and the development database password (`centinela`); error messages name the variable, never the value. The server entry point and the migrate CLI load `<repo>/.env` with `process.loadEnvFile` when it exists; variables already in the environment win, so CI and containers are unaffected.

## S0-07 — Orchestrator behavior at the edges (2026-10-26, S0)

Blank lines are skipped and not counted; a trailing `\r` is stripped; line numbers in rejections are 1-based positions in the input. A parser that throws produces a `parser error` rejection instead of failing the request (the message is not echoed). `Pipeline.ingest` calls are serialized so concurrent requests never interleave batches inside the stateful detector. `createPipeline(options)` accepts `pool` (default event store) and `rulesDir` (default detector) besides component overrides; `createDetector({ rulesDir })` is the factory S2 implements. `ParserRegistry` is a `ReadonlyMap<SourceType, Parser>`.

## S0-08 — Suppression window semantics (2026-10-26, S0)

A candidate folds into the latest alert with the same dedup key when that alert is `new` or `acknowledged` and `candidate.firstSeen - alert.lastSeen <= 15 minutes` (overlaps fold too). `ALERT_SUPPRESSION_WINDOW_MS` and `MAX_ALERT_EVENTS` live in `@centinela/shared` so the in-memory sink and S4's PostgreSQL sink share them. An alert created and then updated within the same `upsert` call is reported (and published) once, as created, with its final state. `createdAt`/`updatedAt` use the wall clock (record keeping), never detection.

## S0-09 — Lint and format (2026-10-26, S0)

ESLint uses `typescript-eslint`'s `recommendedTypeChecked` (type-aware, `projectService`) plus `consistent-type-imports`, `eqeqeq`, `no-explicit-any` and the repo-wide ban on `dangerouslySetInnerHTML` (both the JSX attribute and the `createElement` prop form). `npm run lint` runs ESLint and `prettier --check`. Prettier skips Markdown and the vendored or externally owned folders (`rules/`, `data/`, `tools/`, `content/`, `.github/`), so the kit documents and SigmaHQ files are never reformatted.

## S0-10 — Web shell choices (2026-10-26, S0)

`packages/web/tsconfig.json` is solution-style (`tsconfig.app.json` for browser code, `tsconfig.node.json` for Vite/Vitest configs) so browser code does not see Node types. MSW 3 renamed `onUnhandledRequest` to `onUnhandledFrame`; tests use `'error'` so an unmocked call fails. The `msw/vite` plugin in `worker-only` mode serves `mockServiceWorker.js` on the dev server only (`apply: 'serve'`), so production builds do not ship the worker and nothing generated is committed. Vendor code is split into `react`, `charts` and `vendor` chunks to stay below the 500 kB budget. The language is stored under `centinela.language`; without a stored value the browser's languages decide (`es*` → Spanish). Translation keys are type-checked (`src/i18n/i18next.d.ts`). Vite reads the repository-root `.env` (`envDir`), so one file configures everything.

## S0-11 — Docker and Compose (2026-10-26, S0)

Images use `node:22-bookworm-slim`. The server image installs production dependencies of the server workspace only, keeps code owned by root and runs as `node`; it contains `rules/`, `data/mitre-attack/` and the migrations. The web image is a static build served by `nginxinc/nginx-unprivileged` (uid 101, port 8080), which also proxies `/api` (unbuffered, for SSE) so the browser stays same-origin. Compose binds every port to 127.0.0.1 (overridable with `POSTGRES_PORT`, `SERVER_PORT`, `WEB_PORT`), runs the server with `NODE_ENV=development` by default so the development secrets are accepted, and applies migrations before starting the API. The cloud session script now also runs `npm run db:migrate`.
