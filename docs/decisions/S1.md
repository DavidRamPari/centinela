# Session S1 decisions

## S1-01 — Sample timestamps: RFC 3339 auth logs on Lima time (2026-10-26, S1)

The generator writes auth.log with RFC 3339 timestamps (microseconds and an offset, the rsyslog default on current Ubuntu and Debian) and access.log in the nginx combined format. Every host runs on Lima time (UTC−05:00, no daylight saving), so the files carry `-05:00` / `-0500` offsets while `ground-truth.json` is in UTC. RFC 3164 would make the year depend on when the file is ingested (and S4's demo and end-to-end test would need `--year`); the RFC 3164 path is still fully implemented and tested in the parser. Ground-truth `start`/`end` are rounded out to whole seconds because access logs have one-second precision; every scenario line falls inside its range (tested).

## S1-02 — Length limits and storable text (2026-10-26, S1)

Parsers look at most at the first 65,536 characters of a line (bounding the work per line); `message` and every string field are then cut to 8,192 characters. Parsing the longer prefix means a long URL does not turn a valid access-log line into a rejection, while storage stays within §3.1. NUL characters (rejected by PostgreSQL `text` and `jsonb`) and lone UTF-16 surrogates are replaced with U+FFFD before parsing, so attacker-controlled bytes can never make a batch insert fail. Every parser regex is anchored and free of nested quantifiers; tests feed huge and pathological lines and assert bounded time.

## S1-03 — linux_auth details beyond the §4.1 table (2026-10-26, S1)

- sshd user names are attacker-chosen and may contain spaces or a fake ` from 1.2.3.4 port 1`; the patterns take the *last* ` from <ip> port <n>`, which is the part sshd appended.
- `sshd-session` and `sshd-auth` (OpenSSH 9.8+/10 split processes) count as sshd for actions and logsources; `process.name` keeps the real name.
- rsyslog's `message repeated N times: [ ... ]` is classified by its inner message (one level only) with `syslog.repeat_count = N`.
- Program-specific rows apply only to their program (e.g. `new user:` only from `useradd`); PAM session rows apply to any program. `pam_unix(su:auth)` failures map to `su_failure` (user = `ruser`, target = `user`). sudo's `command not allowed` stays `other`.
- Extra fields, all optional: `source.address` (raw address or host name; `source.ip` only when it is an IP), `process.tty`, `user.id`, `user.home`, `user.shell`, `group.id`, `group.shadow`, `user.changes.by`, `session.id`, `sudo.failed_attempts`. A host name in `rhost=` yields no `source.ip`. IPv4-mapped IPv6 becomes IPv4; IPv6 is compressed (RFC 5952); brackets and zones are stripped.
- RFC 3164 year rollover follows §4.1 literally (also with an explicit `defaultYear`). A date that only exists in the previous year (Feb 29) is read in that year; impossible dates are rejected as `invalid timestamp`.

## S1-04 — Web access log details (2026-10-26, S1)

The optional trailer after the user agent is read as `http.request.time` when it starts with a number (seconds for nginx `$request_time`, as logged otherwise); any other trailing text is ignored instead of rejecting the line. A client that is a host name keeps `c-ip` and `source.address` but gets no `source.ip`. A bare `?` gives no `cs-uri-query`. Quoted fields accept both Apache (`\"`) and nginx (`\x22`) escapes and keep them raw.

## S1-05 — Ingest endpoints (2026-10-26, S1)

- Middleware order: rate limit → bearer token → query validation (`400`) → content type (`415`) → 5 MB body parser (`413`) → pipeline. Unauthenticated and malformed requests are refused before the body is read; failed token attempts count against the rate limit.
- Rate limits are per client IP and live as constants in `src/ingest/router.ts` (120 requests/minute for `/api/ingest`, 30 for `/api/ingest/upload`), overridable through `createIngestRouter` options for tests. Making them environment variables would mean editing `config.ts`, which S1 does not own.
- `application/x-ndjson`: a JSON string is the line; an object with a string `message` contributes that; any other object is passed on as its JSON text (so S5's Sysmon parser can read JSON lines); anything else is rejected as `invalid NDJSON line`. These rejections are merged into the pipeline's summary in line order (still at most 20 samples); rejected lines are replaced by blank lines so line numbers stay right.
- Token comparison hashes both values with SHA-256 and uses `timingSafeEqual`, so neither content nor length leaks. `401` answers carry `WWW-Authenticate: Bearer`.
- `/api/ingest/upload` is simply not mounted in production, so it falls through to the generic `404` problem.

## S1-06 — Event store with `unnest` (2026-10-26, S1)

`insertMany` sends one `INSERT … SELECT FROM unnest($1::uuid[], …, $13::jsonb[])` per chunk of at most 1,000 events: one round trip, thirteen parameters regardless of the chunk size, no SQL built from content, and a chunk is atomic. The `events` table has no `logsources` column; `logsources` are a pure function of `source` and, for `linux_auth`, `fields['process.name']`. `src/parsers/index.ts` exports `linuxAuthLogsources(program)` so S4 can rebuild them when reading events back (web sources always get `[{category: webserver}, {service: nginx|apache}]`).

## S1-07 — Ingest CLI (2026-10-26, S1)

Flags `--source`, `--file`, `--host` (default `unknown`), `--tz` (default `UTC`) are validated with the shared `ingestQuerySchema`; `--year` sets RFC 3164 years; `--parse-only` uses a no-op store and detector to measure parser throughput (the acceptance number). Relative paths resolve against `INIT_CWD` because `npm run -w` changes the working directory. Files are streamed with a small line reader (`src/ingest/lines.ts`) that caps each line at 65,536 characters while reading, so a file with a gigabyte-long line cannot exhaust memory. Exit codes: 0 success, 1 unreadable file or runtime error, 2 bad arguments.

## S1-08 — Generator design (2026-10-26, S1)

- Every component (each host's auth traffic, each web host's visits/crawlers/probes, each scenario) draws from its own mulberry32 stream derived from the seed and a label, so changing one generator does not shift the others. No `Math.random` anywhere (tested).
- Scenario start times are fixed hours into a 3-day run (e.g. `ssh-bruteforce` at 27.2 h → `2026-10-21T03:12:00Z`, as in the §4.3 example) and scale with `--days`. `bruteforce-success`, `post-compromise` and `privileged-user` are one attacker session (login, two sudo commands, `useradd`/`usermod` through sudo, logout), recorded as three scenarios.
- `--small` keeps the same scenario lines and times and generates background traffic only from 5 minutes before to 5 minutes after each scenario (about 7,000 lines instead of about 200,000).
- `ground-truth.json` follows §4.3 and adds `"small": true|false`. `entities.users` for `password-spray` lists the 25 sprayed names; scenarios without a network entity (`privileged-user`, `sudo-not-allowed`) have `ips: []`.
- Background design keeps clear of every vendored SigmaHQ Linux and web rule (zero matches at any level, not just high/critical) and of the §6.1 thresholds: staff mistype at most twice, crawlers and customers produce scattered 404s, user agents carry no vendor URLs and every domain ends in `.example`.
- `@centinela/loggen` now exports `generate()` and its types (same `exports` pattern as `@centinela/shared`) for S4's end-to-end test. The server's sample tests import loggen by relative path so `packages/server/package.json` and the lockfile stay untouched; S4 can add the dependency when it wires `npm run demo`.

## S1-09 — Tests that check samples against SigmaHQ rules before S2 (2026-10-26, S1)

`packages/server/test/samples/sigma-lite.ts` is a test-only evaluator for the subset of Sigma the vendored Linux and web rules use (keywords, field maps, `contains`/`startswith`/`endswith`/`all`, `null`, routing, `and`/`or`/`not`/`1 of`/`all of`). It proves each scenario triggers its expected SigmaHQ rules and the background triggers none, without depending on S2's engine. It builds regexes from rule values, which is acceptable only because it is test code reading the repository's rule files; it must never be used at runtime (S2's engine is the real one).
